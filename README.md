# HH Job Finder

Настольное приложение для ежедневного поиска, сбора, оценки и систематизации реальных вакансий HeadHunter для начинающего специалиста в **Набережных Челнах, Елабуге и ОЭЗ «Алабуга»**.

Проект написан на Python 3.11+, использует PySide6, SQLite, `httpx`, BeautifulSoup, `pandas/openpyxl`. В каталоге уже лежит база `data/jobs.db` с **реальными вакансиями**, собранными 08.11.2026 в несколько щадящих проходов. Тестовые/синтетические вакансии в базу и отчёты не добавлялись.

---

## 1. Что уже работает

- Поиск по всем заданным ключевым словам, сгруппированным через `OR`, чтобы не делать сотни однотипных запросов.
- Дополнительный широкий поиск: все свежие вакансии, стажировки, офисные/клиентские/производственные/творческие роли, категории `professional_role` из справочника HH.
- Поисковая выдачи HH вызывается с `enable_snippets=true`: краткие обязанности и требования собираются прямо из карточек, что позволяет проверять фактический опыт и оценивать вакансию даже до загрузки полной страницы.
- Отдельные запросы по ОЭЗ «Алабуга»: area `1641` (Набережные Челны), `1633` (Елабуга), `1624` (Республика Татарстан) **только со словом «Алабуга» и проверкой адреса/работодателя**.
- Фильтр опыта `noExperience` + `between1And3`; фактический опыт дополнительно проверяется регулярными выражениями по тексту описания. Вакансии с требованием более 3 лет исключаются, а не просто вакансии без слова `Junior`.
- Дедупликация по `id` вакансии, SQLite `PRIMARY KEY` + аккуратный `UPSERT`.
- Сохранение: название, компания, зарплата от/до, валюта, gross/net, город, адрес, опыт, формат работы, занятость, график, обязанности, требования, дата публикации, дата обновления/источник даты, ссылка, ID, ключевые навыки, категория, поисковые теги, оценка и объяснение.
- Оценка 0–100 с объяснением и разбором по факторам. Веса намеренно ограниченны: высокая зарплата без совпадения навыков не превращает непрофильную вакансию в «лучшую». В текущем снимке максимум — **82 балла**, а не 100.
- Фильтры: категория, город, формат работы, минимальная зарплата, вакансии без зарплаты, новые, избранное, исключённые, «Целевой регион» по умолчанию, сортировки.
- Разделы: Главная, Все вакансии, Лучшие совпадения, Категории, Избранное, Настройки.
- История запусков и поисковых запросов, новые вакансии, отслеживание изменений зарплаты и описания.
- Ручной поиск, автообновление через `QTimer`, корректная отмена фоновой задачи при выходе.
- Экспорт текущей выборки / всех / избранного / лучших в `.xlsx`, `.csv`, `.json`.
- Автономный HTML-отчёт с реальными данными: `reports/dashboard.html`.
- Скриншоты всех разделов интерфейса: `screenshots/`.

## 2. Важная правда об API HH

Официальный `GET /vacancies` в 2026 году возвращает **403 Forbidden** для анонимных запросов: требуется OAuth-токен приложения/пользователя. Это подтверждается и практической проверкой из песочницы, и официальной документацией:

- [Документация api.hh.ru](https://api.hh.ru/openapi/redoc) — OAuth2, `Authorization: Bearer {ACCESS_TOKEN}`.
- [HH.ru закрыл публичный API поиска вакансий](https://habr.com/ru/news/1069286/).
- [Официальная спецификация OpenAPI](https://api.hh.ru/openapi/specification/public).

Справочники `/dictionaries` и `/professional_roles` доступны анонимно и приложение использует их всегда: курсы валют, опыт, занятость, графики, форматы работы, профессиональные роли.

### Как приложение обходит ограничение

1. **Основной путь — официальный API.** В Настройках можно вставить `access_token` или `client_id`/`client_secret` и получить токен приложения через `POST /token`. Тогда поиск и детали идут через `/vacancies` и `/vacancies/{id}`.
2. **Если токена нет и API вернул 403**, приложение честно показывает статус и переключается на **щадящий однопользовательский резервный режим** публичных страниц hh.ru: общий лимит запросов, максимум 2 потока для детальных страниц, отдельный медленный лимитер, паузы, обработка 429/5xx/капчи, остановка догрузки при капче.
3. `robots.txt` hh.ru не рекомендует массовый обход URL с параметрами для общих краулеров. Резервный режим можно полностью отключить в Настройках; он предназначен только для личного ежедневного поиска, а не для массового скрейпинга.
4. При временной капче можно сохранить страницу вакансии из браузера и импортировать её локально: `python scripts/import_pages.py ~/Downloads/vacancy_138256023.html`. Сеть при импорте не используется.

**Никаких демонстрационных данных вместо реальных нет.** Если описание ещё не загружено, карточка помечается «Краткая карточка», а интерфейс прямо говорит, что полное описание будет догружено позже.

Приложение не стало «долбить» сайт: сбор поисковых страниц завершился, код получил отдельный лимитер `≥1.25 с`, не более 2 параллельных детальных запросов и общий флаг капчи. ## 4. Запуск

### Linux / macOS

```bash
cd hh_job_finder
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python run.py
```

Или просто `./run.sh` (создаст venv и установит зависимости).

На минимальных Linux-системах PySide6 может потребовать системные библиотеки: `libxkbcommon0`, `libegl1`, `libgl1`, `libxcb-cursor0`, `libxcb-icccm4`, `libxcb-image0`, `libxcb-keysyms1`, `libxcb-render-util0`, `libxcb-shape0`, `libxcb-xinerama0`, `libxcb-xkb1`.

### Windows

```bat
run.bat
```

### Полезные команды

```bash
# Только собрать данные без GUI
python scripts/scan.py --pages 2 --details 100 --delay 0.9 --concurrency 2

# Догрузить описания без повторного поиска
python scripts/scan.py --enrich-only 150 --delay 1.5 --concurrency 2

# Импорт HTML-страниц, сохранённых в браузере
python scripts/import_pages.py ~/Downloads/hh_pages/*.html

# HTML-отчёт из реальной БД без внешних ресурсов
python run.py --report reports/dashboard.html

# Скриншоты всех разделов в offscreen-режиме
QT_QPA_PLATFORM=offscreen python run.py --no-auto --screenshots screenshots

# Один скриншот конкретного раздела
QT_QPA_PLATFORM=offscreen python run.py --no-auto --screenshot screenshots/best.png --page best
```

Логи: `data/logs/app.log`, `data/logs/scan.log`, `data/logs/initial_scan.out`.

### Используемые методы API

- `GET /dictionaries` — опыт, занятость, график, формат работы, курсы валют.
- `GET /professional_roles` — широкие категории профессий.
- `GET /areas` — справочник регионов; ID `1641`, `1633`, `1624` зафиксированы в конфиге.
- `GET /vacancies` — основной поиск, если есть OAuth-токен.
- `GET /vacancies/{id}` — полная карточка, если есть OAuth-токен.
- `POST /token` — получение токена приложения по `client_id`/`client_secret`.

Параметры поиска: `text`, `area`, `experience`, `professional_role`, `period`/`search_period`, `order_by=publication_time`, `page`, `per_page`, `host=hh.ru`, `no_magic`. Пагинация с нуля, обработка `pages/found`, ограничение `per_page` до 100 для API и 20 на страницу для HTML-выдачи.

## 7. Хранение данных

SQLite, WAL, индексы по оценке/дате/категории/городу:

- `vacancies` — уникальные вакансии, `id` как `PRIMARY KEY`; `is_new`, `is_favorite`, `enriched`, `excluded`, `score`, `content_hash`, `first_seen_at`, `last_seen_at`, `last_changed_at`.
- `search_runs` — история запусков, источник, статус API, счётчики, ошибки.
- `search_queries` — история каждого поискового запроса и его параметров.
- `changes` — реальные изменения зарплаты, описания, названия, опыта или формата.
- `meta` — служебные значения.

Защита от повторного сохранения: `INSERT ... ON CONFLICT` по `id`. Первое появление полного описания считается **обогащением**, а не изменением работодателем.

## 10. Честно об ограничениях

- **Официальный поиск вакансий без токена недоступен.** Приложение полностью реализует API-режим, но токен HH выдаёт только зарегистрированному приложению; в комплект он не входит. Без токена используется резервный режим hh.ru.
- **Капча.** HH может временно запросить капчу на детальных страницах. Приложение не решает капчу и не обходит её агрессивно: оно останавливает догрузку, сохраняет уже найденные вакансии и повторит позже. Локальный импорт сохранённых HTML-страниц — запасной путь.
- **Дата обновления.** Публичная страница HH обычно не содержит отдельного `dateModified`. Пока изменений не зафиксировано, показывается дата публикации с пометкой `published_fallback`; при реальном изменении зарплаты/описания приложение ставит `updated_at = время фиксации` и `updated_at_source = change_tracking`. Это явно видно в карточке и в экспорте.
- **Нормализованная зарплата** — ориентир для фильтра: валюты переводятся в рубли по курсу справочника HH, почасовая/посменная оплата приводится к месяцу эвристически. Это не расчёт оклада «на руки».
- **HTML-разметка hh.ru может измениться.** Парсеры опираются на `data-qa`, `<data value>`, JSON-LD `JobPosting`; есть тесты и понятные точки для правки.
- Не реализовано: автоматическая отправка откликов, решение капчи, обход robots.txt для массового скрапинга, LLM-оценка, синхронизация с облаком. Это не требовалось задачей.
- Не все 748 вакансий имеют полное описание в снимке из-за капчи: 279 карточек обогащены полностью, ещё 469 содержат краткие сниппеты HH, явно помечены как «Краткая карточка» и не выдаются за полные. Приложение продолжает догружать их при следующих запусках.

## 11. Безопасность и частота запросов

- `settings.json` содержит токен/секреты только локально, файл создаётся с правами `0600`.
- Резервный режим по умолчанию использует паузу `0.75 с` между поисковыми запросами и `≥1.25 с` между детальными страницами, не более 3 потоков поиска и 2 потоков деталей.
- Повторные попытки только для `429/5xx/сетевых ошибок`, с экспоненциальной паузой и учётом `Retry-After`.
- При закрытии окна `SearchWorker.stop()` отменяет корутины, главный поток ждёт завершения до 15 секунд; принудительное завершение — только крайняя мера.
- Ошибки пишутся в ротируемый `data/logs/app.log`.
